Environmental health · Technical case study

A reusable environmental exposure library

From raw monitoring records to 64.8 million temporal patterns and a deployed research application.

Role
First author; pipelines and research application
Data
U.S. EPA monitoring records, 2004–2024
Scale
64.8 million temporal patterns
Stack
Python, SLURM, Flask, Docker, Nomad

The problem

Exposure averages can hide short episodes, repeated peaks, and changes over time. Extracting these patterns separately for every study also repeats data preparation. The SMARTER library makes local temporal representations available for retrieval and reuse.

What I built

  • Python pipelines for extracting and checking hourly and daily patterns from EPA records.
  • SLURM jobs for running the processing workflow on the University of Utah’s CHPC cluster.
  • A Flask application for searching, filtering, and downloading patterns by location and time, deployed with Docker and Nomad.

This work was carried out within the collaborative SMARTER project. I am first author of the IEEE ICHI 2026 methods paper.

From observations to retrieval

Design decisions

Two temporal scales
7- and 30-day windows retain local dynamics at weekly and longer scales.
Explicit data quality
Observation-completeness criteria and bounded interpolation address gaps without treating all missing periods as observed data.
Normalization and selection
Site-level normalization and quality-based window selection support comparison and reduce redundant candidates.
Context travels with the pattern
Temporal and geographic metadata allow patterns to be connected to a study’s exposure window and monitoring area.

Research use

The library was used to characterize exposure before diagnosis in a hypersensitivity pneumonitis cohort. Read the clinical linkage case study.

Evidence and limits

The collection contains approximately 64.8 million patterns from 2004–2024 monitoring records. The publication documents the methods, and the hosted application provides access to the research resource. These establish the scale and implementation of the resource; they do not establish predictive improvement for every downstream task.

Runtime, peak-memory and query-latency benchmarks are not reported here. Clinical comparisons are exploratory.
